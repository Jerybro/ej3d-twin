模型 API 控制台

發布制模型註冊表（publish-registry）：把訓練好的模型發布成穩定 model_key， 以統一契約對外提供 predict／評估／最佳化端點；數位孿生的每個 block 即由此取用模型，並附使用量與稽核。

三層架構
L1 · 資料

資料 API

資料集與欄位的統一存取層（/agatha/data）。模型的輸入特徵源頭，對標 Tukey 資料facade。

L2 · 發布註冊

模型註冊 API

本頁。把 (dataset_id, model_id) 發布成穩定 model_key，脫鉤後仍可統一 predict／治理開關。

L3 · 孿生綁定

Block 取用

孿生流程的每個 block 以 model_key 呼叫 predict，把模型接進即時模擬與健康度預警。

線上試呼叫 · predict

輸入

選一個模型，填入特徵值後送出（統一 predict 契約）。
L3 block 綁定時，只需 model_key ＋ inputs 即可呼叫，無需知道底層 (sid, mid)。

回應

回傳依模型 task 而定（品質→預測值、異常→風險值/門檻）。
尚未呼叫。
API 端點（namespace /agatha）
POST/agatha/model/publish/發布 (dataset_id, model_id) → model_key
GET/agatha/find_model_list/模型清單（?include_usage=yes 附使用量）
GET/agatha/model/{model_key}/capability/能力與 input/output schema（綁定前查）
POST/agatha/model/{model_key}/predict/統一推論（L3 核心）
POST/agatha/model/{model_key}/evaluate/評估指標
POST/agatha/model/{model_key}/optimize/配方最佳化（reg/hybrid）
POST/agatha/model/{model_key}/threshold/異常門檻試算（anomaly）
PATCH/agatha/model/{model_key}/enabled/啟用/停用（治理開關）
GET/agatha/model/{model_key}/usage/單模型使用量與稽核
DEL/agatha/model/{model_key}/移出註冊表（不刪底層）
呼叫範例
// L3 block 綁定 — 只需 model_key + inputs
const r = await fetch('/agatha/model/<MODEL_KEY>/predict/', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ inputs: { feature_a: 1.23, feature_b: 4.56 } })
});
const out = await r.json();   // → 預測值 / 風險值（依 task）
